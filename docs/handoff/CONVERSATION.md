# 需求与修改聊天记录摘要

这是为跨设备接续整理的用户可见需求与修改记录，不包含完整聊天数据库、内部推理、凭据或工具输出。以下“要求”不等于每个平台均已实现；实际状态请结合源码、验证记录与交接说明。

## 产品沿革

- 最初要求制作参考 Typora 的 Markdown 软件，启动快、清晰高亮，支持中文斜杠命令，例如 `/公式` 插入 `$$` 公式块，并在 GitHub 建项目。
- 新建文件保留原文档，用多标签切换；可保存 Markdown 或导出 PDF。支持 Windows 和 macOS，仓库公开，README 面向下载试用的用户。
- 更新检测从 GitHub 获取版本；大版本可弹窗并允许不再显示。后来改用公开静态更新清单，避免 GitHub API 限流。安装/升级沿用目录，清理旧程序内容，保留用户数据及快捷方式。
- 用户曾要求软件安装到 `D:\Moye`，创建桌面与开始菜单入口。源码维护不得因此移动已装软件。

## 编辑与格式

- 修复所有按钮无响应、向上方向键跳多行、分屏无法向下滚动、切换侧栏尺寸错误等问题。要求代码按职责分类，保存本地目录导航方便后续开发。
- 加入源码/阅读实时分屏、YAML/YML 阅读，以及 `Ctrl+数字` 切换标题等级；相同等级再次按下恢复正文。
- 未命名文档的编号从当前会话可用的 1 开始；修复查找控件过小、长标题换行与下一行重叠。
- 后续加入主题渐变、图片、用户 JavaScript 插件。用户强调颜色清晰明亮、不过分花哨；品牌改为 Mini Mark，图标选已展示的 C 方向，字略往左，并同步主题色、仓库名与发布文案。
- 公式编辑器可以通过模板点击创建公式、写回当前 Markdown 的 `$$` 块，也可复制成供 Word/WPS 识别的结构化公式。接收软件兼容性不能仅凭生成文本保证。
- HTML 可编辑并在本地 Chrome 或内置浏览器运行；打开不自动执行，也不强制关联为默认应用。选中文字必须有清晰的高亮。

## Rev 版本、云文档与文档操作

- 用户把正式版本展示改为 `Rev v1.0.0`，之后沿用 `Rev v1.0.1`、`Rev v1.0.2` 等；内部 4.x 版本保留防降级用途，不作为新版公开 Release 名称。
- 同一 Rev 大版本可检测、覆盖更新，不强迫重新安装；未来到 Rev v2.0.0 才触发大版本弹窗。不要在迁移中重新创建旧 v4.x Release。
- Markdown/YAML/HTML 文件分别使用文档图标，不能全部照搬软件图标。
- 云存储使用用户自己的 GitHub 账号，先登录再连接自己的 `MiniMarkDisk`；没有仓库时经确认创建。支持下载编辑、保存同步、目录分类、本地/云文档切换；本地文档不默认上传。
- 云文档支持删除文件/文件夹、重命名和冲突保护。授权界面自动复制完整授权码，也可手动复制。macOS 的确认框不能依赖 Windows 弹窗实现。
- 新建未命名 Markdown 的首行是非空 H1 时自动以标题命名；首行非 H1 不更新。手动重命名/保存/云绑定之后不要继续覆盖名字。
- 用户曾要求免费个人 macOS 证书，后明确“开始发布，不用管签名了”；当前源码与文档使用 ad-hoc，不能把它说成 Apple Developer ID 或已公证。不要购买证书或恢复已取消的签名项目工作。

## 桌面 Rev v1.0.3 最近需求

- 左侧可切换单文档/工作区文档；在新建、打开外加入打开文件夹，显示工作区目录的所有文件并按需读取。
- 点击左上 Mini Mark 图标/名称打开与菜单相同的更新窗口；窗口展示当前/候选版本更新内容，改进布局。
- 可导入图片作为主题背景，自行调整透明度。
- 用户要求项目级 `AGENTS.md` 支持各工作区协作；源码迁入 `D:\MiniMark`，已安装软件不移动。不要再把 Mini Mark 当作 WXHelper 子项目。
