# GitHub 云文档维护

此文档面向维护者。用户说明在 README 的“云文档”章节。

## 登录配置

Mini Mark 使用 GitHub OAuth App 的设备授权流程。注册应用并启用 Device Flow 后，将公开 Client ID 写入 `public/github-oauth.json` 的 `clientId`。开发时也可设置 `MINIMARK_GITHUB_CLIENT_ID` 环境变量。不要填写 Client Secret、个人访问令牌或其他凭据。

默认申请 `repo` scope，以便创建和读写用户自己的私有 `MiniMarkDisk`。GitHub OAuth 的这个权限范围不限于单个仓库，授权页面会显示实际范围。软件自身只访问登录用户的 `MiniMarkDisk`，不读取其他仓库。若未来改用权限更细的 GitHub App，需要同时重做安装授权、创建仓库和用户令牌刷新流程，不能仅替换 Client ID。

发布工作流会拒绝空 Client ID。真实 OAuth 登录、私有仓库创建和跨设备冲突需在发布前人工验证；模拟测试不能替代这一步。

OAuth 应用可以保持 `Expire user access tokens` 开启。设备授权返回的访问令牌、刷新令牌及两者有效期一起写入系统凭据存储；旧版的单令牌记录仍可读取。令牌接近过期时按需刷新，同一进程内的并发请求共用一次刷新。刷新请求不携带 Client Secret。

GitHub 刷新成功后会立即使旧令牌对失效，因此必须先保留并安全持久化新令牌对，再验证账号。网络错误不能清除已有登录；确认刷新凭据失效时才要求重新登录。退出登录或取消授权后，迟到响应不得恢复凭据。接口收到 401 时最多刷新并重试一次，不对超时、409 或 422 自动重试写入。

## 模块

| 目录 | 职责 |
| --- | --- |
| `src/features/cloud` | 登录界面、目录浏览、文件位置选择、请求超时与取消 |
| `native/Cloud` | GitHub 请求、令牌有效期与刷新、Windows 凭据管理器、文档同步协调 |
| `macos/Cloud` | GitHub 请求、令牌有效期与刷新、macOS Keychain、文档同步协调 |
| `native/Documents/DocumentWorkspace.cs` | 本地与云端基线、恢复与脏状态 |
| `macos/Documents/DocumentStore.swift` | macOS 文档模型与会话 |
| `tests/cloud.spec.ts` | 模拟宿主协议的界面回归 |
| `native-tests/CloudTests.cs` | 模拟 GitHub HTTP、路径校验、冲突和账号隔离 |

前端 `cloudRequest` 只接受预定义动作，不能提供任意 URL。令牌和设备授权内部码不进入网页消息、会话、日志或仓库。用户看到的设备授权码不同于内部 `device_code`。

`copyAuthorizationCode` 请求只传公开的 `code`。宿主检查它与尚未过期的当前登录授权码完全一致，再通过系统剪贴板复制全文；不会复制内部设备码或访问令牌。首次登录在复制回执后打开 GitHub，复制失败不阻断授权，界面仍保留手动复制按钮。取消登录后不接受迟到的授权码回执。

macOS 主 WKWebView 通过 `WKUIDelegate` 显示创建仓库与删除确认框。仅接受本地应用主框架，取消是默认选项；窗口关闭或网页进程退出时结束待处理回调。HTML 预览和插件不获得此权限。

## 删除

`delete` 请求包含 `owner`、`path`、列表快照 `sha` 和 `entryType`（`file` 或 `dir`）。不能使用顶层 `type` 表示条目类型，它保留给宿主消息的 `cloudRequest`。

两平台从默认分支的最新提交逐层读取非递归 Git tree，严格核对目标类型与快照 SHA。删除目录直接移除对应子树，包含未显示的资源文件。重建受影响的祖先树时保留全部兄弟条目，空父目录放入 `.gitkeep`；不允许删除仓库根目录。最多支持 16 层路径，树响应被截断时拒绝写入。

仅创建一个删除提交，以原 head 为唯一父提交；更新前再次读取分支，必须仍等于最初 head，最后使用 `force: false` 更新分支。SHA 冲突、分支前进、权限失败或网络错误均不自动重试删除，不强制覆盖远端。创建了树或提交但未更新分支不会改变可见文档。

GitHub 更新引用接口不提供 expected-head 的原子比较条件。最后一次读取与更新之间仍存在极短的强制回退竞态；普通并发新提交会被非快进检查拒绝。删除期间不要从其他工具强制改写分支历史，不把该接口描述成完整的 compare-and-swap。

宿主将删除与文档保存、绑定互斥。只有确认分支更新成功，才将同账号、同路径（目录包含子路径）的已打开标签解绑为本地；保留正文、名称、修订号和原本地保存基线。失败不解绑。前端删除请求允许较长超时；关闭窗口并不承诺撤销已经发出的远端写入。

## 重命名

文档标签的 `renameDocument` 操作由宿主区分草稿、本地文件和云文档。云文档只允许在当前目录修改文件名，不使用“先删除再上传”。

云端操作复用 Git tree 校验与重建：核对源 blob SHA，拒绝已存在的目标，保留源 blob SHA 和模式，创建一个提交后以 `force: false` 更新分支。未保存正文不会上传，云端内容基线不会改变；完成后更新已打开文档的云路径，不移动其本地副本。与保存、删除互斥，失败不自动重试。

重命名与删除具有相同的引用更新竞态限制。网络中断导致提交结果无法确认时，应先刷新云目录核对，不直接重复操作。

## 保存约定

- 新建和本地打开的文件默认不上传。首次云保存必须由用户选择目录和文件名。
- `CloudBinding` 保存 `owner`、`path`、`sha`、`baseline`，不存储令牌。
- 本地 `baseline` 与 `cloud.baseline` 分开保存。切回本地时，未写入本地文件的更改仍标为未保存。
- 打开云端文件时使用 metadata SHA 对应的 blob，避免把新内容与旧 SHA 混在一起。
- 更新文件必须携带原 SHA。409/422 不自动覆盖、不重试 PUT；失败保留正文和原基线。
- 同步成功只更新已发送快照的基线。关闭文档前再次检查 revision 和 dirty。
- 退出或取消登录递增会话代次，迟到结果不能变成新账号的保存成功。
- 不自动后台重试写入，避免用户切回本地后仍然上传。
- 目录加载完成前不能创建文件夹或提交云保存；加载失败时显示路径与内部目标保持一致，重开窗口不保留旧目录显示。
- 网络请求不在启动阶段运行，云功能按用户操作发起；网络请求采用异步 API，macOS 解析与凭据操作位于独立队列。

云端文本限制为 5 MB，允许 Markdown、YAML、HTML、TXT。文件夹用 `.gitkeep` 保留。目录路径禁止绝对路径、反斜杠、空段、`.`、`..`、`.git` 和控制字符。

## macOS 免费签名

默认打包使用 `codesign --sign -` 的 ad-hoc 签名，不产生 Apple 证书，也不等于公证。免费个人团队的开发签名用于本机测试，不作为公开下载包的 Developer ID 身份。此项目不会自动注册付费 Apple Developer Program。

个人开发证书的前提、操作与验证见 [macOS 签名](mac-signing.md)。未在实际 Mac 钥匙串中确认有效签名身份之前，不将证书申请标为完成。

## 发布前检查

1. 配置公开 Client ID，并完成一次真实登录、创建私有仓库、保存、退出、重新登录。
2. 另一台设备修改同一文件，确认旧 SHA 保存失败且正文保留。
3. 执行前端、浏览器、原生和真实 WebView 测试；由 Actions 验证 macOS。
4. 发布目标 Rev 版本，确认四个系统下载包、校验和与更新清单均可获取。正式标签与附件只使用 Rev 名称，不恢复已移除的内部版本 Release。
