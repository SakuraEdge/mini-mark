# 工作区维护

工作区目录与已打开文档的会话分别管理。切回单文档、关闭工作区或目录读取失败，不丢弃正文和标签。

## 协议

- `folderRequest` 带 `requestId`、`action`。动作是 `choose`、`restore`、`list`、`close`。
- `list` 使用授权 `rootId`、相对 `path` 和非负 `offset`。返回 `folderResponse` 的 `data` 包含 `root`、`path`、`entries`、可选 `nextOffset`；空或 null 的 `nextOffset` 表示最后一页。
- `choose` 只能通过用户点击打开文件夹触发原生选择器，取消返回 `cancelled: true` 并保留原目录。
- `root` 包含进程内标识、名称和显示路径。根目录存于数据目录 `workspace-folder.json`，只有前端处于工作区模式时请求恢复，不在默认启动时扫描磁盘。
- 每个条目包含 `name`、相对 `path`、`type`（`file` 或 `directory`）、`supported` 和可选 `link`。显示所有文件，无法安全打开的名称、链接和不支持的格式禁用。
- `openWorkspaceFile` 是文档操作，携带活动正文快照、`rootId`、相对路径。不能把文件打开请求误当作普通目录查询；结束后发送工作区和操作完成回执。

## 读取与状态

两平台在后台读取单层目录，每页最多 500 项，目录优先并稳定排序。根目录切换后迟到响应不得覆盖新树。刷新使子目录缓存失效，展开时重新获取。

Windows 检查每级重解析点，读取期间持有祖先目录句柄；macOS 通过 `openat` 与 `O_NOFOLLOW` 逐层访问并核对设备号、inode。相对路径不得越出授权根，文件只读普通 UTF-8 文本，限制 20 MB，不执行 HTML、可执行程序或链接目标。打开相同路径优先复用已打开标签，不能覆盖其未保存正文。

目录分页不是磁盘快照，外部程序在分页之间增删文件时可能改变排序位置；刷新重新获取目录。没有自动递归文件监控，也不创建或删除工作区目录内容。

浏览器预览使用用户选择的目录文件列表，只能访问其中的 `File` 对象，保存仍是下载。浏览器不能完整表达空目录，也不会跨启动保留目录访问权。正式桌面版使用原生接口，不受此限制。

## 验证

`tests/workspace.spec.ts` 覆盖共享交互与模拟宿主；Windows 原生与实际 WebView2 测试覆盖路径、分页、链接、打开及草稿保护；macOS 自测和实际 WKWebView 在 Actions 执行。测试必须使用隔离根目录和配置，不指向用户文档。
