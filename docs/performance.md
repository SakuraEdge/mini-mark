# 启动性能记录

测量日期：2026-11-04。

**v0.1 尚未达到稳定 1 秒内冷启动的目标。** 不以窗口出现、网页开发服务器就绪或已缓存的空白界面代替完整启动。

## 口径

程序在收到初始文档、建立编辑器、等待 `document.fonts.ready`，再经过两帧绘制后报告就绪。

- 外部计时：`Process.Start` 前到收到就绪诊断文件。
- 内部计时：托管入口 `Main` 到编辑器就绪。
- 渲染计时：WebView 页面开始加载到编辑器就绪。

内部计时不包含进程创建及 CLR 进入 `Main` 前的耗时，不能代替完整启动时间。

## 已观察到的结果

测试机：Intel Core Ultra 5 228V，约 32 GB 内存，Windows x64，系统 WebView2 156.0.4314.58。测试时存在大量运行中的应用，CPU 采样达到 100%，数据不代表空闲机器。

| 构建与条件 | 窗口已显示 | WebView 初始化完成 | 编辑器就绪 |
| --- | ---: | ---: | ---: |
| WinForms 发布构建，新配置目录 | 1,618 ms | 3,364 ms | 5,931 ms |
| WinForms 发布构建，已有草稿目录 | 779 ms | 2,177 ms | 4,420 ms |

上表均为从托管入口计时。另一次连续进程重启测试出现约 10 秒的 WebView 配置目录锁等待，不能将这组数据当作正常热启动成绩。测试脚本已加入等待上一次 WebView 退出的逻辑，并提示未释放的情况。

前期 WPF 原型的外部计时约 5–8 秒；最终选择 WinForms 宿主，但尚不能据此宣称性能目标达成。

## 已实施

- 系统 WebView2 承载本地静态资源，不启动 Node 服务或网络请求。
- 原生 WinForms 宿主、.NET ReadyToRun 发布。
- TypeScript + CodeMirror 6，无额外前端 UI 框架。
- 语言解析器按需加载。
- HTML 导出模块与字体内嵌处理只在导出时加载。
- 草稿写入节流，编辑事务不等待磁盘。

## 复现

在较空闲的系统中，使用一个不存在的输出目录：

```powershell
./scripts/benchmark.ps1 `
  -Exe ./release/Moye/Moye.exe `
  -OutputDirectory ./benchmark-results `
  -Runs 5
```

脚本只使用隔离的草稿/WebView 配置目录，数据写入 `results.json`。`--benchmark` 是开发测量参数，完成就绪后程序自动关闭。

下一阶段需要在空闲机器测量冷启动与正常间隔的重复启动，分析 CLR/窗口初始化、WebView 初始化和前端模块执行，再决定是否需要更低开销的原生宿主。性能目标仍是 1 秒左右可编辑；这个版本先提供功能完整、可检验的基础。
