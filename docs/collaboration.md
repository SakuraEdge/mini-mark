# 多工作区协作

## 工作区与分支

主工作区存放整合后的 Mini Mark 源码。其他任务使用独立分支与 Git worktree，共享提交历史但不共享未提交修改。不要把源码目录当成已安装的软件目录。

在当前工作区检查：

```powershell
git rev-parse --show-toplevel
git rev-parse --path-format=absolute --git-common-dir
git worktree list
git status --short
```

新增工作区先核对路径不存在、分支未被使用，再执行。例如从主工作区运行：

```powershell
git worktree add ..\MiniMark-workspaces\heading-fix -b fix/heading-fix
```

每个工作区独立执行 `npm ci`。`AGENTS.md` 和本文件属于版本控制：新工作区从包含这些文件的提交创建；旧工作区应先检查未提交修改，再由负责人合入协作规则提交。独立 clone 不共享本地登记，需通过任务消息及提交交接，不能假设能看到其他 clone 的未提交状态。

## 本地协作登记

跨 worktree 的本机协调目录为 Git 公共目录下的 `minimark-coordination/`。通过上述 `--git-common-dir` 动态解析，不写死 `.git` 或盘符。此目录不进入 Git 或发布包。

- 每项任务独占一个 `<task-id>.md` 文件，避免多人反复覆盖同一张表。
- 开始时写任务、负责人、分支、工作区、基准提交、负责文件、接口约定和验证计划。
- 编辑前查看其他活动任务；发现文件交叉先协调。记录只是约定，不是文件锁；时间过久不代表任务已结束。
- 交接时补充提交哈希、实际测试结果、待办和整合者，状态改为 `ready`。
- 整合者检查 diff 并合入，重跑受影响的测试后标记 `integrated`。不得只看到登记就宣称代码已合入。
- 不登记令牌、用户文档内容或私人会话；不要自动删除其他任务登记。

推荐模板：

```text
任务：
负责人：
状态：active / ready / integrated / blocked
更新时间：
工作区：
分支：
基准提交：
负责文件：
共享协议/依赖：
验证计划：
交接提交：
实际验证与未覆盖项：
待办/阻塞：
整合者：
```

## 交接与整合

1. 开始前同步任务范围和文件归属，共享协议由一个负责人定义。
2. 子任务只修改自己负责的文件；同一工作树内不自行提交别人的改动。
3. 提交前复核 diff，交接完整提交哈希、测试及已知限制。
4. 整合者选择 merge 或 cherry-pick，先检查冲突与依赖，不盲目覆盖。
5. 主工作区完成整体验证后更新 `docs/validation.md`；用户要求发布时才启动发布流程。

文档和交接不能代替实际执行。工作树、分支、提交及测试结果以工具读取为准。
